## 3. Architecture and interface changes

- **Web:** Next 16.4.6/React 19.3.1/TypeScript/Tailwind 4.3.5. `/` shows clearly fictional readonly fixtures; `/api/demo` bridges server-side to API; `/health` checks web process. No database secret becomes a public browser variable.
- **API:** GET `/health/live`, `/health/ready`, `/api/v1/demo/cases`, `/api/v1/knowledge`, `/api/v1/capabilities`; protected GET `/api/v1/private/cases/{case_id}` and POST `/api/v1/private/consents`. FastAPI generates only the implemented foundation contract/reference; planned P01 outline is not represented as implemented.
- **Migration:** `0001_demo` creates only demo_cases metadata and a synthetic-only Boolean check. Alembic version state is tracked. Downgrade drops that fictional table; rollback tests operate only on a disposable `_test` database. No patient/genomic/consent/audit schema or pgvector corpus is created.
- **Authentication/consent:** Protocol boundaries only; identity returns no principal and consent always denies. No valid user/token, role grant, invitation, consent state machine or bypass configuration.
- **Knowledge/rules:** Empty provider/unavailable response; approved corpus empty, sources empty. No embeddings, model calls, medical rules/probabilities or clinical interpretation.
- **Observability/errors:** Generated request IDs, method/status/duration logs only; no path/query/body/header/raw exception logging through the provided server startup. JSON error envelope and no-store headers. Readiness requires expected migration plus fixture availability.
- **Decision:** [ADR-005](../docs/adr/ADR-005-hackathon-foundation.md) selects prototype boundaries and records npm/lint override tradeoffs. Historical ADR-001 to ADR-004 and clinical approvals remain unresolved.
- **Infrastructure:** Local Compose only, ports bound to 127.0.0.1, non-root app containers and no-new-privileges. Development verification images include test tooling; no production deployment, cloud, secrets manager or healthcare integration.
