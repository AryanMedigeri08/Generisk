# Risk contract v1 — P06

Written before implementation, 2026-11-16. Synthetic-only educational arithmetic, no clinical authorization. Stable P07 integration surface; no P07 implementation here.

Every engine envelope has `contract_version:"gen-risk-1"`, `state`, `message_keys` (identifier tokens only), `label:"Synthetic demonstration. Educational estimate. Not a diagnosis. Not for clinical use."`, `each_pregnancy_independent:true`, `caveat_codes`, `numbers`, `genes`, `bindings`. Independence message key: `risk.each_pregnancy_independent`. No localized risk prose in outputs beyond the required label. Unknown results have empty numbers, never a numerical placeholder.

Numbers are `{exact:{num:int,den:positive_int},natural_frequency:{k:int,n:positive_int},basis:"derived"|"sourced"|"user_scenario"}`. Fractions reduced exactly; natural frequency is k in n, including 0 in 1. Ratios need not be probabilities. `numbers` keys depend on mode; no decimal rounding in v1. State codes: COMPUTED, OWN_CARRIER, OWN_NO_FINDING, SHARED_CARRIER, SINGLE_CARRIER, NEITHER_CARRIER, UNKNOWN, REVIEW_REQUIRED, EDUCATIONAL_ONLY_NO_CALCULATION, UNSUPPORTED, NOT_COMPUTED, NO_SHARED_FINDING, UNAVAILABLE. Unknown inputs never contribute a zero. Each gene result has the same state/message/caveat/numbers fields (without recursively nested genes).

Bindings identify rules version/hash, panel ID/version/hash and separate reference-values version/hash. Authenticated results additionally bind own report ID/revision/input version and `scope_hash`; the latter commits current consent versions and both partners' input/source bindings without exposing partner report identifiers. No timestamps or random IDs in computed envelopes: identical inputs/bindings serialize identically. No result persistence.

## Public what-if

`POST /api/v1/risk/whatif` is stateless/public, JSON <=4096 bytes, extra fields forbidden, no cookies/CSRF needed at API, no database or audit. Explicit proxy allowlist strips private cookies/CSRF. Other risk method/path combinations are denied. Inputs use bounded exact `{num,den}` integers (numerator/denominator <=1e6, denominator >0), not floats, NaN, infinity, identifiers or prose. These bounds keep output integers exact in JavaScript's integer range. Population/relationship are echoed as controlled tokens for population/residual modes.

- `mode:"mendelian"`, `gene_symbol` (panel enum), `a_status`, `b_status`: carrier/no_pathogenic_variant_detected/variant_uncertain/not_tested. Supported known statuses yield affected/carrier/neither fractions 1/4,1/2,1/4; 0,1/2,1/2; or 0,0,1 under the idealized covered-gene assumptions. These are not measured negative-test residual estimates; `IDEALIZED_STATUS_MODEL` and `NEGATIVE_NOT_ZERO_RESIDUAL_UNKNOWN` caveats prevent that inference. Shared gene always adds GENE_LEVEL_ONLY and `risk.shared_gene_conditional`; variant confirmation is outside scope. Educational-only genes yield no number.
- `mode:"consanguinity"`, `gene_symbol`, `relationship` (unrelated/second_cousins/first_cousins_once_removed/first_cousins/double_first_cousins/not_sure), `population` (user_scenario/unspecified), optional `q`. Explicit q requires user_scenario basis; absent q uses only an exact gene/population reference match, otherwise UNKNOWN. 0<q<1. Numbers related/unrelated/ratio/F follow q²(1−F)+qF and q². not_sure gives UNKNOWN + `risk.counsellor_context`; no calculation.
- `mode:"residual"`, `gene_symbol`, `population`, optional `c`,`d`, `relationship`. Supply both c,d from the same user_scenario, or neither from one exact population reference. 0<c<1, 0<=d<=1. Posterior c(1−d)/(1−cd). `posterior_carrier` only; never a related couple residual estimate. `couple_state:"NOT_COMPUTED"` and reason key `risk.related_residual_not_modelled` for related/unknown relationships; unrelated uses `risk.individual_residual_only`. d=1 gives exact zero under ideal assumptions; c>0,d<1 stays positive.

## Authenticated assessment

`GET /api/v1/risk/my-assessment`: owner-only, current processing plus explicit own assessment consent. Uses only current active v2 source; unresolved selected input produces REVIEW_REQUIRED without reading historical content as current. Own genes return OWN_CARRIER/OWN_NO_FINDING, uncertain/educational states, **no partner/pregnancy estimate**. Missing consent denied. Minimal transactional audit metadata only.

`GET /api/v1/risk/couple-assessment`: uses the caller's sole joint relation or optional `X-Risk-Joint` canonical UUID header selecting a relation they belong to. Multiple relations without selection, non-member or invalid selection remain neutral unavailable. The public what-if proxy never forwards this header; no identifiers enter URLs. Both current processing and existing joint assessment grants plus separately scoped educational disclosure grants are mandatory. Declined/withdrawn/not enrolled/stale all return HTTP200 exactly `{"state":"UNAVAILABLE","message_keys":["risk.unavailable"],"label":"Synthetic demonstration. Educational estimate. Not a diagnosis. Not for clinical use."}`. No binding/reason/partner data in that body.

Released couple `genes` contains **shared carrier genes only** with conditional Mendelian outcomes. Non-shared partner statuses/genes are omitted, including different-gene carrier findings; NO_SHARED_FINDING is the same envelope category for neither/one/different carriers. The pure engine still supports each per-gene one-carrier calculation for hypothetical inputs; own status summary is available separately. Uncertain/gapped partner inputs suppress couple numbers and details globally (REVIEW_REQUIRED). This intentionally limits the release surface rather than leaking partner-only findings.

Consent uses existing `/api/v1/me/consents` with additive `purpose:"educational_risk"`: own assessment uses own `case_id`/input version and no joint; educational disclosure uses joint/output version and no case. Existing joint assessment remains unchanged. Purpose is bound into `scope_key`; no new table, auto-grant or placeholder-review flag. Legacy disclosure still requires its reviewed placeholder. Expiry, refusal, withdrawal, supersession, CSRF, optimistic version/idempotency and required audit remain P03 operations.

Authenticated GET accepts optional `X-Risk-Binding` (64 hex chars). Initial explicit request omits it; subsequent views send the last `bindings.scope_hash`. Changed report/scenario/consent/rules/reference bindings cause HTTP409 `STALE_BINDING` for own assessment (including withdrawal); couple uses the identical neutral unavailable response. The UI clears displayed output and requires explicit new calculation after stale/unavailable; no auto-recompute. Read and revocation share P03's serialized transaction; results are a snapshot, not a revocable copy after viewing.

No X-linked/mitochondrial/dominant/variant-level/compound-heterozygote severity inference, related-couple conditional residual model, population selection inference, persistence, clinical triage or LLM/RAG. Missing references stay null; the P05 panel/hash and v1 tests remain unchanged. APR/H and clinical gates unchanged.
