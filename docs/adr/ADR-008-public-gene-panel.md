# ADR-008 — Public gene references and synthetic report v2

2026-11-16. ACCEPTED for the owner's P05 authorization/DEC-012 only. GENERISK_SOLUTION.md controls hackathon phase names: deterministic educational risk is P06, education studio/content is P07; neither is implemented here. Clinical gates/APR/H statuses unchanged.

Use a packaged, Pydantic-validated public JSON panel, generated JSON Schema, source registry and SHA-256 version. HGNC verifies approved symbols/IDs; NLM MedlinePlus Genetics supplies attributed condition/inheritance context. Summaries are our own wording; no OMIM/GeneReviews text, variants or patient data. Public API/page is read-only, isolated from private reports, and not an educational studio. The panel is an illustrative subset, never the Abu Dhabi clinical panel.

Reference frequency/q/detection fields remain null when population/assay-specific values are not defensible. Mark their basis illustrative with an explicit unavailability reason, never invent sourced numbers or derive carrier frequencies from prevalence. Source metadata binds URL, retrieval date, exact field and licence note. Severity is a broad variable descriptor, not triage. CYP21A2/SMN1 are educational_only for pseudogene/copy-number complexity; MEFV is also educational_only because inheritance/penetrance context exceeds this gene-only demo. Gene symbols alone cannot distinguish HBB conditions or establish a clinical result.

V2 retains the synthetic envelope, binds the exact panel hash, and admits only panel gene symbols/controlled gene-level statuses. Unknown genes or panel versions are unsupported. Uncertain validity/status, excluded/not-tested genes or missing observations/coverage require review; unknown never becomes absent. V1 remains unchanged. No schema/data migration is needed: existing immutable TEXT/JSONB/provenance rows store both versions.

P04 supports multiple immutable report families, but does not choose one case-wide scenario and rejects conflicting revision-one imports. P05 adds a fixture-only scenario selection operation for v2: select/import a current predefined family revision, clear other v2 active heads, advance P03 input versions and invalidate old permissions/outputs transactionally. It cannot select a stale revision within an amended family, change v1 source history, accept arbitrary data, auto-grant processing or bypass required audit. Repeating the already-current choice is a no-op; changing choices uses fresh current processing and expected-version/idempotency checks. A predefined none-to-CFTR amendment preserves its original. Existing import/amend behavior remains for v1.

Known limits: no clinical validity/conformance, Arabic names unreviewed/null, numeric reference values unavailable, public demo credentials/loopback/DB-owner controls, no risk engine or clinical interpretation. Existing empty KnowledgeProvider and unavailable ClinicalRulesProvider remain. Any later risk output must bind current source/panel/rules versions and separately authorized scope.
